# 对话式内容生产工作流方案

## 1. 为什么改成对话式工作流

这个项目早期曾经尝试沿着“独立产品”方向推进，包括：

- 浏览器页面
- 本地 HTTP 服务
- 文案模型配置
- 图片模型配置
- 文稿生成、审核、出图的一体化网页流程

但复盘后发现，这条路线的成本和目标并不匹配。

为了把它做成一个产品，需要长期承受：

- 模型 API 配置和兼容
- 单独 token 计费
- 前后端维护
- 图片模型适配
- 状态管理和报错处理

而这个项目真正想解决的，其实是：

- 稳定产出符合要求的小红书知识卡片笔记
- 保持风格一致
- 支持人工审核和持续迭代
- 让新的 AI 模型也能快速接手既有规范

所以项目重新定义为：

`以对话为入口、以人工审核为闸口、以本地文稿为确认载体、以最终图片为交付物的内容生产工作流。`

---

## 2. 当前标准流程

### Step 1：用户给出话题

例如：

- 城市
- 食物与饮料
- 品牌与消费场景
- 汽车 / 新能源
- 生活方式符号

### Step 2：AI 生成审核稿

我先根据当前规范生成一份可审核的文稿，内容包含：

- 标题
- 封面主标题 / 副标题 / 封面列点
- 2 到 6 张知识卡文案
- `#话题`

这一步的目标不是直接出图，而是先得到一份内容上可判断、可修改的草稿。

### Step 3：本地审核文档 skill 创建专题文件夹

每个专题在 `outputs/` 下都有一个独立文件夹。

推荐命名：

- `outputs/20260322_红酒/`
- `outputs/20260322_茶叶/`

### Step 4：本地审核文档 skill 保存本地审核文档

审核稿生成后，要保存成一份本地文档，供用户直接修改。

推荐主文档文件名：

- `01_审核稿.docx`

这个阶段的关键规则：

- 先保存文稿，再进入人工修改
- 用户修改以本地文档为准
- 这份文档是后续进入出图阶段前的唯一确认载体
- 这一步由独立的“本地审核文档” skill 负责，不再由写作 skill 直接承担

仓库中已准备模板：

- `templates/topic_draft_template.docx`

当某个专题的 `01_审核稿.docx` 已经存在时，可以同步把 `outputs/topic_library_final.xlsx` 里对应话题的“备选话题”单元格写成超链接，直接跳转到这份文档。

同步脚本：

- `tools/update_topic_library_links.py`

### Step 5：用户在本地文档中修改并确认

用户可以直接修改本地文稿文档。

只有当用户明确确认：

- “文稿无误”
- “可以出图”
- “以文档内容为准进入下一步”

这类意思时，才进入下一阶段。

### Step 6：从本地已确认文档读取内容

进入图片生成前，不再以上一轮聊天里的文本为准，而是以本地已确认文档为准。

然后把这份文档内容整理成统一结构：

- `ApprovedNotePack`

推荐保存为：

- `02_approved-note-pack.json`

### Step 7：进入出图阶段

这一阶段只负责把已确认文稿稳定做成图片：

- 1 张封面
- N 张知识卡
- 可直接上传

这一步不再重写内容，不再擅自回改文稿。

## 3. 当前边界划分

### 文稿阶段负责什么

- 选点
- 标题
- 封面文案
- 知识卡解释深度
- 语气和风格
- `#话题`

这一阶段对应写作 skill，只负责“写什么”。

### 本地审核文档阶段负责什么

- 创建 `outputs/YYYYMMDD_话题/`
- 生成或更新 `01_审核稿.docx`
- 保证文稿版式适合直接在 Word 里修改
- 维护 `topic_library_final.xlsx` 中的话题超链接
- 把本地文档确立为审核阶段唯一确认载体

### 出图阶段负责什么

- 封面视觉实现
- 知识卡排版
- 行距、留白、层级
- 图片导出

这一阶段对应出图 skill，只负责“怎么把已确认文稿做成图”。

### 明确禁止

出图阶段默认不得：

- 擅自回改文稿
- 重新判断内容够不够深
- 重新判断图片“看起来空不空”并借机回改内容
- 绕过本地已确认文档，直接用旧聊天文本出图

如果确实需要回改内容，必须由用户明确重新打开文稿审核阶段。

## 5. 后续推荐使用方式

### 方式一：日常单篇生产

1. 你给出话题
2. 我生成审核稿
3. 保存到本地专题文档
4. 你直接修改文档
5. 你确认
6. 我读取本地文档并出图

### 方式二：规则打磨

1. 用具体样稿试写
2. 你指出长期问题
3. 我同步更新 skill / reference / 文档
4. 以后默认继承新规则

---

## 6. 一句话总结

`以后每个专题都先落成本地审核文档，用户确认后再从本地文档进入最终出图阶段；仓库的价值在于规范、结构、模板和 skill，而不是独立产品壳。`
